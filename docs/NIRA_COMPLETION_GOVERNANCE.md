# حاکمیت تکمیل نیرا

## جایگاه
این سند مکمل **سند جامع نیرا** است و مسیر اجرای آن را در پروژه NIRA تعریف می‌کند.

## ترتیب اعتبار
1. قابلیت عملی موجود و اثبات‌شده NIRA، اگر از الزام متناظر سند جامع قوی‌تر باشد، حفظ می‌شود و ملاک کار عملی است.
2. سند جامع نیرا مرجع هدف، حداقل تعهدات و مسیر تکمیل قابلیت‌های فاقد پیاده‌سازی یا اثبات کافی است.
3. تجربه‌ها، الگوها، کنترل‌ها و درس‌آموخته‌های موجود NIRA و تجربه‌های حاصل از کار با کارخانه نرم‌افزار Arvin باید حفظ شوند؛ هیچ بازنویسی صرفاً برای هم‌شکل‌کردن با سند مجاز نیست.
4. هر تغییر باید ابتدا وضعیت واقعی GitHub را بررسی کند و سپس با Issue → Branch → Commit → PR → CI → Evidence پیش برود.
5. صرف ایجاد مستند، Workflow، تست یا فایل به معنی تکمیل قابلیت نیست؛ تکمیل باید با شواهد اجرای واقعی اثبات شود.

## هدف نهایی
هدف نهایی پروژه NIRA تحقق عملی سند جامع نیرا است؛ یعنی تبدیل NIRA به کارخانه‌ای که چرخه Idea → Product → Software → Test → Security → Release → Operation → Monitoring → Learning → Optimization → Next Product Version را به‌صورت پیوسته، امن، موازی، کنترل‌شده و مبتنی بر شواهد اجرا کند.

## روش تکمیل
- ابتدا قابلیت‌های موجود NIRA نسبت به سند جامع شناسایی و حفظ شوند.
- سپس شکاف‌ها به Taskهای کوچک، مستقل و قابل اجرا تبدیل شوند.
- کارهای مستقل موازی و وابستگی‌ها کنترل شوند.
- هر شکاف مهم دارای شواهد قابل بازسازی GitHub باشد.
- Self-Fix، Recovery، Learning و Optimization خود کارخانه نیز جزو محصول محسوب شوند.
- تکمیل یک Wave یا Release پایان کار نیست؛ چرخه بعدی باید ادامه یابد.

## اصل عدم تخریب
قابلیت موجود و اثبات‌شده‌ای که از سند جامع قوی‌تر است نباید با نسخه ضعیف‌تر جایگزین شود. در صورت تعارض، **قابلیت عملی قوی‌تر حفظ می‌شود** و در صورت نیاز سند یا معیار اجرایی به‌عنوان Baseline بالاتر مستند می‌گردد.

## اصل شواهد
وضعیت هر الزام باید در نهایت یکی از این حالت‌ها را داشته باشد:
- Implemented + Proven
- Implemented + Partially Proven
- Partial
- Missing
- Unknown

هیچ الزام مهمی نباید بدون بررسی GitHub به‌عنوان تکمیل‌شده گزارش شود.

## اولویت تکمیل
1. Real Execution و Evidence
2. Orchestration و Task Engine
3. Quality و Security Gates
4. Failure / Recovery / Self-Fix
5. Product Lifecycle از ایده تا انتشار و عملیات
6. Continuous Operation و Version Evolution
7. Memory، Learning، Technical Debt و Optimization
8. Multi-Project و Cross-Repository Production
9. Factory Self-Review و Self-Improvement

## حفاظت از تجربه
تجارب عملی NIRA و درس‌آموخته‌های پروژه‌های قبلی، به‌خصوص تجربه‌های به‌دست‌آمده از کارخانه Arvin، بخشی از سرمایه عملیاتی NIRA محسوب می‌شوند و باید در Memory، Documentation، Tests، Workflows و Architecture در صورت وجود شواهد مناسب حفظ و قابل استفاده مجدد باشند.

## معیار پایان
پایان پروژه زمانی اعلام نمی‌شود که فقط اسناد و اجزای معماری موجود باشند. معیار اصلی، توانایی اثبات اجرای واقعی چرخه‌های تعریف‌شده در سند جامع نیرا در پروژه‌های واقعی و بازسازی شواهد آن از GitHub است.
